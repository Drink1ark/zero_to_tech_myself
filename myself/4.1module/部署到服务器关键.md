# Linux 服务器静态网站部署指南

本文以 Ubuntu/Debian 服务器为例，介绍如何通过 GitHub 克隆项目，并使用 Nginx 部署静态 HTML 网站，最终通过服务器公网 IP 访问网站。

## 1. 生成 SSH 密钥

在服务器终端执行：

```bash
ssh-keygen -t ed25519 -C "your_email@example.com" -f ~/.ssh/github_ed25519
```

参数说明：

- `-t ed25519`：指定密钥类型为 Ed25519。
- `-C`：添加注释，通常填写 GitHub 邮箱。
- `-f`：指定密钥文件保存路径。

如果出现是否设置密码的提示，可以根据需要设置。

生成的文件：

```text
~/.ssh/github_ed25519       # 私钥，必须保密
~/.ssh/github_ed25519.pub   # 公钥，可以添加到 GitHub
```

查看公钥：

```bash
cat ~/.ssh/github_ed25519.pub
```

复制输出的完整内容，打开 GitHub：

https://github.com/settings/keys

选择 **New SSH key**，将公钥添加到 GitHub 账户中。

> 注意：不要将私钥 `github_ed25519` 上传到 GitHub，也不要发送给他人。

### 配置 SSH 使用该密钥

编辑 SSH 配置文件：

```bash
nano ~/.ssh/config
```

添加：

```sshconfig
Host github.com
    HostName github.com
    User git
    IdentityFile ~/.ssh/github_ed25519
    IdentitiesOnly yes
```

设置权限：

```bash
chmod 700 ~/.ssh
chmod 600 ~/.ssh/github_ed25519
chmod 644 ~/.ssh/github_ed25519.pub
chmod 600 ~/.ssh/config
```

测试 GitHub SSH 连接：

```bash
ssh -T git@github.com
```

如果出现类似下面的提示，说明认证成功：

```text
Hi username! You've successfully authenticated, but GitHub does not provide shell access.
```

## 2. 克隆 GitHub 仓库

进入项目存放目录：

```bash
cd ~
```

使用 GitHub 仓库的 SSH 地址克隆项目：

```bash
git clone git@github.com:用户名/仓库名.git
```

例如：

```bash
git clone git@github.com:Drink1ark/zero_to_tech_myself.git
```

克隆完成后进入项目目录：

```bash
cd zero_to_tech_myself
```

查看项目文件：

```bash
ls -la
```

找到包含网站首页 `index.html` 的目录。

例如：

```text
zero_to_tech_myself/
└── myself/
    └── 4.1模块化/
        ├── index.html
        ├── css/
        ├── js/
        └── text-lab.html
```

## 3. 配置 Nginx

安装 Nginx（如果尚未安装）：

```bash
sudo apt update
sudo apt install nginx -y
```

编辑默认站点配置：

```bash
sudo nano /etc/nginx/sites-available/default
```

配置示例：

```nginx
server {
    listen 80 default_server;
    listen [::]:80 default_server;

    root /home/admin/zero_to_tech_myself/myself/4.1模块化;

    index index.html index.htm index.nginx-debian.html;

    server_name _;

    location / {
        try_files $uri $uri/ =404;
    }
}
```

其中：

```nginx
root /home/admin/zero_to_tech_myself/myself/4.1模块化;
```

是网站根目录，必须指向实际包含 `index.html` 的文件夹。

例如，如果项目实际位于：

```text
/root/zero_to_tech/zero_to_tech_myself/myself/4.1模块化
```

那么 `root` 应设置为：

```nginx
root /root/zero_to_tech/zero_to_tech_myself/myself/4.1模块化;
```

**注意：** `root` 后面不要写 `index.html`，只需要写网站目录。

## 4. 配置文件读取权限

Nginx 通常以 `www-data` 等非 root 用户运行，因此需要确保它能够穿过网站路径中的目录，并读取网站文件。

如果网站位于：

```text
/home/admin/zero_to_tech_myself/myself/4.1模块化
```

可以执行：

```bash
sudo chmod o+x /home/admin
```

该命令允许其他用户穿过 `/home/admin` 目录，但不会允许列出目录内容。

网站文件本身也需要具有读取权限。例如：

```bash
sudo chmod -R o+rX /home/admin/zero_to_tech_myself/myself/4.1模块化
```

其中：

- `o+r`：允许其他用户读取文件。
- `X`：仅对目录或已经具有执行权限的文件增加执行权限。

> 权限设置需要根据网站实际路径进行调整。如果网站位于 `/root` 下，修改 `/home/admin` 的权限并不能解决 `/root` 路径的访问问题。生产环境更推荐将静态网站放在 `/var/www/` 下。

## 5. 检查并重启 Nginx

修改配置后，先检查语法：

```bash
sudo nginx -t
```

如果显示：

```text
syntax is ok
test is successful
```

说明配置检查通过。

重新加载 Nginx：

```bash
sudo systemctl reload nginx
```

如果 Nginx 尚未启动，可以执行：

```bash
sudo systemctl enable --now nginx
```

查看运行状态：

```bash
sudo systemctl status nginx --no-pager
```

## 6. 配置服务器安全组

登录云服务器控制台，找到实例的安全组规则。

确保入方向允许：

| 协议 | 端口 | 用途 |
|---|---:|---|
| TCP | 22 | SSH 远程连接 |
| TCP | 80 | HTTP 网站访问 |
| TCP | 443 | HTTPS 网站访问（后续配置） |

如果 80 端口未开放，外部浏览器可能无法访问网站，即使 Nginx 已经正常运行。

## 7. 访问网站

在浏览器中访问：

```text
http://服务器公网IP/
```

例如：

```text
http://47.104.214.5/
```

如果配置正确，Nginx 会读取网站根目录下的 `index.html` 并展示首页。

## 8. 常见问题排查

### 访问网站出现 404

检查 Nginx 的 `root` 是否指向正确目录：

```bash
ls -l "/home/admin/zero_to_tech_myself/myself/4.1模块化/index.html"
```

如果网站目录实际在 `/root` 下，应将 `root` 修改为对应的完整路径。

### 访问网站出现 403

通常与目录权限或文件读取权限有关。

查看目录权限：

```bash
namei -l "/网站目录/index.html"
```

确认 Nginx 用户能够穿过每一级目录，并读取 `index.html`。

### Nginx 配置修改后没有生效

执行：

```bash
sudo nginx -t
sudo systemctl reload nginx
```

查看错误日志：

```bash
sudo tail -n 50 /var/log/nginx/error.log
```

### 本地能访问，公网无法访问

检查：

1. 云服务器安全组是否开放 TCP 80 端口。
2. Nginx 是否监听 80 端口。
3. 服务器防火墙是否拦截 80 端口。

查看监听状态：

```bash
sudo ss -lntp | grep ':80'
```

